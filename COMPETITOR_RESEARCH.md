# Competitor research — verified findings and feature breakdowns

**Research date:** 2026-11-21
**Targets:** Onetime Secret, Yopass, Privnote, Password Pusher, PrivateBin, Bitwarden Send
**Purpose:** product/engineering input for OneShotLink. No competitor UI, copy, logos, fonts, or implementation was copied into this repository.

## 1. Method and evidence standard

- Six parallel investigators, one per competitor, grounded in the repository's `.claude/agents/` reviewer personas. Each was instructed to record an exact URL, the text actually observed, and a confidence label for every claim.
- Labels used throughout: **VERIFIED** = page/repository file fetched and quoted; **PARTIAL** = search-result snippet, API summary, or second-hand observation; **UNKNOWN** = blocked, timed out, or not found. A failed fetch is reported with its URL and status rather than filled by memory.
- `@reverse-engineer-anything` was loaded and applied. Its MCP tools were **not connected** in this session (no REA tools advertised); per the skill's recovery rules, client configuration was **not** changed without approval. The documented CLI fallback was used on a public shipped artifact: PrivateBin's production `privatebin.js`, fetched from `https://privatebin.net/js/privatebin.js` on 2026-11-21. Re-fetched and re-verified during the final review: **214,084 bytes, SHA-256 `e1007ca68ada7f942f346bd7f280c1d394633933776eb8a7642a722ebc88a2b1`**. REA CLI (`npx -y rea-agents@6.7.0 analyze-javascript-application /tmp/opencode/rea-privatebin --json`, exit 0) produced Evidence ID `ev_1a3af0a84f86c86ee5f7f44096e2f2a878e6cc9071e5a68801b2b7386031838c`, application graph `jag_8d566172979260dcf5d63bd638ee41f95d5a28967927e331143d139f7a263d71`, and 14,624 visited AST nodes, 10,017 semantic nodes, 7,989 relations, 3,515 explicit unknowns. (An earlier snapshot in this session quoted a different hash/Evidence ID for the same statistics; that identifier could not be reproduced and is superseded by the values above.) REA's own limitation is retained: **inert syntax only — no bundle execution**, so recovered names such as `PasteEncrypter`/`burnAfterReading` are static candidates, not observed runtime behaviour.
- Clean-room constraint for **Onetime Secret only**: it is the original this repository clones. Its source code, JS bundles, network calls, private APIs, logos, illustrations, fonts, and GitHub source tree were deliberately **not** inspected. Only public pages and public documentation were used. Other competitors are open-source research targets; their public repositories were permitted evidence.
- `@stageshow` was used for the product-engineering coordination artifact (`docs/competitor-posture.html` and its rendered preview), applying its restraint and framing rules to a single still.

## 2. Executive summary

Verified highlights:

- **Onetime Secret** is the closest product competitor: two-token secret/receipt flow, a confirm-then-reveal step that prevents link scanners from burning a secret, five share-nothing regions, `simple`/`full` self-hosting, API v2, and EU prices €0/€35/€125 per month. Its public documentation **contradicts itself** on whether the passphrase is part of the encryption key, on region count, on email pixel tracking, and on Cloudflare usage.
- **Yopass** is actively developed (3,246 stars; latest release 16.2.0 on 2026-11-18; Rust server now default) and unusually rigorous: published threat model, cross-backend one-time claim tests, and a 2026 advisory. It has **no hosted service** (€149/year self-hosted business licence) and explicitly excludes rate limiting and key enumeration from its bug scope.
- **Privnote** is reachable again (HTTP 200 for public pages) but its privacy policy is dated 2018 and it carries ads/third-party trackers. Its "nobody can read your note" claim is a **claim**, not an audited fact; a c.2008 first-person account describes server-side encryption/decryption, and a 2010–2012 EuroPriSe seal explicitly **excluded** `privnote.com`. Documented phishing lookalikes caused ~$18k in losses over five days in 2024.
- **PrivateBin** is a mature pastebin with browser-side AES-256-GCM (PBKDF2, 100k iterations), key in the URL fragment, rich attachments/discussions, JSON-LD API and 13 community clients. It deletes burn pastes on `GET` **before** client decryption — a wrong password still destroys the secret. 2.1.1 (2026-11-04) fixed three security issues; no modern independent audit was found.
- **Password Pusher** is a mature Rails product with atomic DB row-lock view claims, audit logs, an inbound-requests feature and a broad API; its own docs explicitly say there is **no client-side encryption** and that uploaded files are **not** encrypted by the application. Defaults are 7 days / 5 views — a view *budget*, not one-time delivery.
- **Bitwarden Send** is **active**, not deprecated: official 2026 roundup and 2026.11.0 release notes list new Send events, Manage Send policy, email verification and vault-item sharing. Its password is explicitly **not** an encryption key (source comment), limits are 1,000 text characters / 500 MB files, and its own docs warn the link is "full access" and expiry does not remove a recipient's saved copy.

I independently re-fetched two load-bearing sources after the investigators finished: Bitwarden's release notes (confirming "New Send events" and "Manage Send policy", and that Key Connector MongoDB deprecation is a **different component**) and Onetime Secret's `llms.txt` (confirming API v2 stable, v1 legacy, v3 preview, five regions and the two-identifier secret/receipt model). The latter fetch returned `llms.txt` rather than `/en/share/`, the same redirect behaviour the investigator reported; the share-page findings in §4.1 came from its successful HTML fetch.

## 4. Per-competitor evidence

### 4.1 Onetime Secret (clean-room constrained: public pages/docs only)

**Workflow (VERIFIED).** `https://onetimesecret.com/` describes "Paste your secret → Share the link → Gone after viewing". `https://docs.onetimesecret.com/en/share/` documents that opening the link shows a confirmation page **without consuming**, and only "Click to reveal" retrieves the content — "A mail scanner or chat preview that only loads the page does not consume it". Creation returns a **secret link** (`/secret/`) and a **receipt link** (`/receipt/`); the receipt shows *New / Previewed / Revealed*, lasts twice the secret's lifetime, and lets the owner burn an unread secret.

**Security copy contradictions (all VERIFIED fetches).** Current docs say "The passphrase is an access check, not the encryption key for the content"; `https://onetimesecret.com/en/about/` says "we include that in the encryption key … We only store a bcrypt hash of the passphrase". Principles say "No email we send contains tracking pixels"; the Privacy Statement says emails "might contain a pixel tag". Docs list five regions; the Privacy Statement names only EU and US. The Privacy Statement cites Cloudflare; an August 2026 changelog entry describes moving off Cloudflare and deleting the zone.

**Architecture claims (VERIFIED as claims).** "Encrypted in transit and at rest" on every plan; no cipher/KDF named on any fetched page (UNKNOWN). Five share-nothing regions with separate accounts and no cross-centre operations; Stripe for cross-region billing. Self-hosting: `simple` needs only Valkey/Redis; `full` adds SQL (SQLite default, PostgreSQL supported); "the application never terminates TLS, so a proxy in front of it is assumed".

**Limits (VERIFIED).** Anonymous 7 days / 100 KB; Free 14 days / 1000 KB; paid 30 days. EU monthly prices €0 Basic, €35 Identity Plus, €125 Team Plus. Identity/Team plans remove rate limits; audit trail is Beta; IP allowlisting and workspace branding are listed as "Coming soon", and Team Plus mentions "custom signup controls" (**PARTIAL** — the exact "Not available yet" wording and the items "per-domain sign-up validation"/"custom privacy defaults" were not observed verbatim; "Basic is called Free in-app" is also **PARTIAL**). The share-page markdown fetch redirected to `llms.txt`; the quoted share text came from the HTML fetch.

**Recent direction (VERIFIED).** Changelog: SAML 2.0 for self-hosted v0.26.14 (2026-10-01), organizations/SSO/incoming secrets in v0.25 (2026-04-30), GitHub/Google/GitLab sign-in (2026-11-16), 50% nonprofit discount (2026-10-08). Blog: 12+ languages (2025-12-12), UK region (2026-02-06).

### 4.2 Yopass

**Workflow (VERIFIED from homepage mockup, README, API docs; live SPA not driven).** Browser generates a key and encrypts with OpenPGP; server stores ciphertext with an expiry; link is `https://host/#/s/<id>/<key>` so the fragment key never reaches the server; recipient decrypts locally; one-time record is removed on first `GET`. A licensed "secret request" flow uses a browser keypair, stores only the public key, and puts a 16-hex fingerprint in the link so the responder can detect substitution.

**Security model (VERIFIED).** `SECURITY.md` is unusually candid: "The server checks that a submitted message is a well-formed armored `PGP MESSAGE` … armor alone cannot prove that a payload is genuinely encrypted … Treat the API as accepting arbitrary caller-supplied ciphertext." Rate limiting and UUID/key enumeration are explicitly **out of scope** for bug reports. `CONTRIBUTING.md` documents that secret-request history keeps private keys and management tokens **unencrypted in `localStorage`**. GHSA-4v9j-h5v5-4vjw: sender-chosen Argon2 parameters could stall client decryption; fixed in 16.2.0; the advisory notes a one-time secret is deleted on fetch **before decryption finishes**.

**Stack (VERIFIED).** Rust server default (`server/`), Go retained as `jhaals/yopass:go`; React/TypeScript SPA (`website/`) with Vitest + Playwright; Redis/Memcached/DynamoDB-style one-time claims; file storage disk/database/S3. GitHub API: 3,246 stars, 451 forks, pushed 2026-11-20; release 16.2.0 published 2026-11-18.

**Limits (VERIFIED).** No hosted service; €149/year self-hosted business licence buys OIDC, webhooks, audit logging, read receipts, secret requests, branding, and >1 MB uploads. Default max secret length 10,000 bytes; default max file size 512 KB capped at 1 MB without licence; expirations 1 h / 1 day / 1 week with configurable 1 min–90 day bounds.

### 4.3 Privnote

**Workflow (VERIFIED from fetched HTML/FAQ).** Single textarea, optional password with strength meter, destruction-notification email with a 7-character reference name, and TTL options: after reading (default), 1 h, 24 h, 7 d, 30 d. **Timed modes are explicitly multi-read** — "independently of how many times the note is retrieved, the note will be deleted only after that specified time". Unread notes are deleted after 30 days. The FAQ honestly states the recipient can copy/screenshot and that "Privnote doesn't try to protect the note contents from being copied".

**Claims vs evidence.** Privacy policy claims "at no time is any note held in any readable format state at Privnote" and "nobody (including Privnote's administrators) can read a note" — **CLAIM (VERIFIED as text), architecture UNVERIFIED**. Public HTML loads `gibberish-aes.js`; the fragment-key URL shape is consistent with a 2020 Krebs quote about a *lookalike* clone ("the key after # in the URL can be replaced by arbitrary characters and the note will still open", implying the real service's key is meaningful) and a 2012 HN discussion of a similar service ("the stuff after the hash is the decryption key; the HTML anchor never reaches the server") (**PARTIAL** — no current independent teardown of privnote.com was located; live pages returned a Cloudflare 403 this pass and Wayback snapshots were used). A c.2008 first-person post describes the **server** generating the key, encrypting, decrypting and rendering plaintext; the 2010–2012 EuroPriSe seal covered `certified.privnote.com` and explicitly excluded `privnote.com`, is now expired, and even advised users to verify the encrypting JavaScript manually. No audit of the current service was found (UNKNOWN).

**Business/risk (VERIFIED).** Free, ad-supported (Clickio CMP, AdSense slots, Cloudflare Insights); policy last modified 2018-05-25; footer build string 2018-05-25; operator Gletin S.A. (Uruguay). Krebs 2020 and 2024 document lookalike domains that read/modify notes and swap Bitcoin addresses, with ~$18k stolen over five days in 2024. `blog.privnote.com` returned 403; `websearch` returned HTTP 402 on all calls.

### 4.4 Password Pusher

**Identity and reachability (VERIFIED).** "Share passwords, text, files & URLs securely with self-deleting links and full audit logs"; in production since 2011 (GitHub repo created 2011-12-28), operated by Apnotic. `https://passwordpusher.com/` timed out over HTTPS; `http://` returned 200 and redirected to `https://eu.pwpush.com/`. The correct docs host is `docs.pwpush.com` — `docs.passwordpusher.com` and `help.passwordpusher.com` do not resolve. Web search returned HTTP 402.

**Workflow (VERIFIED from create-page HTML, source templates and docs; no live push executed).** One page with Text / Files / URL / QR tabs and a passphrase/password/PIN generator. Expiration is expressed as "delete after N days **or** after N views, whichever comes first" — hosted UI defaults 3 days / 5 views, OSS defaults 7 days / 5 views (configurable 1–90 days, 1–100 views). Options: unlock phrase, "Require a click to reveal", "Let the recipient delete it", and an API-helper drawer that emits equivalent cURL/Python/Ruby calls. The reveal page is deliberately unbranded on the free tier, shows a countdown in days and remaining views, and offers "Delete This Secret Link Now" when permitted; a preliminary `/p/:token/r` click-through exists specifically because email/chat link scanners "eat up views" (FAQ). Owner audit log records creation, views, failed views, expiry and deletion with IP, user agent and referrer.

**Security model (VERIFIED from source/docs).** Puma, ActiveRecord, Lockbox field encryption (`has_encrypted :payload, :note, :passphrase`), Solid Queue, Devise. `docs.pwpush.com/docs/security/` states **"Password Pusher does not provide custom client-side encryption"** and that uploaded files are **not** encrypted by the application (recommends S3 SSE or encrypted volumes). `config/initializers/lockbox.rb` reads `PWPUSH_MASTER_KEY` but ships a hard-coded 64-hex fallback; `PWPUSH_MASTER_KEY_PREVIOUS` supports rotation. `claim_view!` uses `with_lock { reload … }` and fails closed by clearing the payload if the audit row cannot be persisted. A 2,000-row audit cap exists per push. Passphrase attempts are limited to 5/min per push (Rails `rate_limit to: 5, within: 1.minute, only: :show, if: -> { params[:passphrase].present? }, by: -> { params[:id] }`). `pushes_controller.rb` also documents "Passphrase gate before any payload access or view claim" — relevant to the reveal-ordering comparison in §6. An earlier note said "Ruby ≥3.4.3 / Rails 8.1"; release `v2.17.4` is titled "Security - Update to Ruby 4.0.10" (2026-11-19), so Ruby 4.0.10 is the current target; Rails was not re-verified. The docs also say "128-bit SSL" in one place while pricing says TLS 1.2+ — an internal inconsistency.

**API (VERIFIED).** v2 Beta (JSON, bearer token): `/api/v2/version`, `/api/v2/generate`, `/api/v2/pushes` (create/show/preview/audit/destroy), `/active`, `/expired`, `/notify_emails`; hosted docs also list `/api/v2/requests/:token/respond`, workspaces and accounts. Pagination 50/page up to page 200. Rate limits: generator 30/min per IP, audit GET 15/min per IP (burst 5/10 s) and 30/min authenticated; 429 + `Retry-After`. v1 is deprecated.

**Limits/pricing (VERIFIED).** Text payload 1 MB, QR 1,024 chars, 10 files/push, "no hard limits on file upload size — files up to 4 GB have been successfully tested". Hosted EU prices in USD: Free $0, Solo $19/mo ($190/yr), Team $29 ($290/yr, 3 users), Organization $49 ($490/yr, 5 users); 14-day trial requires a card. Self-Hosted Pro: Starter $59/mo ($708/yr), Advanced $79 ($948/yr), Enterprise $119 ($1,428/yr). Files, branding and custom domains start at Solo; RBAC/webhooks at Team; OIDC at Organization. Repo: 3,253 stars, pushed 2026-11-20, release v2.17.4 on 2026-11-19. OSS licence Apache-2.0. README says 31 UI languages while `config/defaults/settings.yml` lists 34 `enabled_language_codes` — **internal mismatch**. An earlier claim that the docs portal says 30 was not reproducible (`/docs/` and `/docs/translations/` returned 404) and is withdrawn. Hosted create-page defaults (3 days / 5 views) and the API-v2 rate-limit numbers in §4.4 remain **PARTIAL**: `/p/new` rendered only a JS shell this pass and `https://pwpush.com/help/api` was not fetched.

### 4.5 PrivateBin

**Workflow and UX (VERIFIED from public instance HTML + source).** Single page with expiration select (5 min…3 days, default 1 hour), `Burn after reading`, `Open discussion`, password input, attachments (multiple files, drag/drop, clipboard paste), `Plain Text / Source Code / Markdown`, `Create`, then `New / Clone / Raw text / Save document / Email / QR code / Copy link` and a delete token. ~36 locales and a dark-mode toggle. FAQ: "PrivateBin does not have a concept of access control in itself".

**Crypto and key handling (VERIFIED from wiki + source; corroborated by REA static analysis).** Browser uses PBKDF2-HMAC-SHA256 with 100,000 iterations, 8-byte random salt, 16-byte IV, AES-256-GCM with a 128-bit tag; the base58 key lives in the URL fragment; a stale JS comment says "10000 iterations" while the actual constant is 100000. REA's static graph of the shipped `privatebin.js` recovered candidate names including `PasteEncrypter`, `CryptoData`, `getRandomBytes`, `decryptOrPromptPassword`, `burnAfterReading`, `changeBurnAfterReading`, `attachmentPreview`, `passwordDecrypt`, `decryptionError` — consistent with the source, but **not proof of runtime execution**.

**Important reliability difference (VERIFIED).** `Paste::get()` deletes burn pastes at `GET` time, and the client calls `Model.getPasteData()` **before** `decryptPaste()`/`requestPassword()`. A wrong password, rotated key, or corrupt record therefore still consumes the secret. A `#-` fragment prefix triggers a load-confirmation step specifically so URL scanners do not trigger deletion.

**Security posture (VERIFIED).** Strict CSP (including `frame-ancestors 'none'`), CORP, COEP, `no-referrer`, `nosniff`, and `X-Frame-Options: deny`; `Cross-Origin-Opener-Policy: same-origin` exists in source but is commented out (issue #970), so it is not sent. Delete token is HMAC-SHA256 verified with `hash_equals`. Metadata deliberately **not** encrypted: creation timestamp, expiry, format, discussion flag, IP-derived icon. README requires HTTPS and says a server admin can be legally forced to log the decryption key. 2.1.1 (2026-11-04) fixed SVG-preview same-origin script, `sizelimit` circumvention DoS and Markdown attribute issues; 2.0.5/2.0.6 fixed XSS. The 2014 ZeroBin audit (4 hours, Taylor Hornby) and the project's issue-tracker record of addressing it are VERIFIED; "no modern independent audit exists" remains an absence claim (**PARTIAL** — external search was blocked by HTTP 402/CAPTCHA, so it cannot be asserted as verified). 8,762 stars; released 2.1.1; pushed 2026-11-20.

**Limits (VERIFIED).** Default `sizelimit` 10 MiB; `fileupload = false` by default; `[traffic] limit = 10` seconds between posts per IP (viewing exempt); purge batch 10; public instance (`privatebin.net`, observed directly) offers 5 min / 10 min / 30 min / 1 hour (default) / 3 h / 6 h / 12 h / 1 day / 3 days — no `never` — while self-hosted config allows `never = 0`. JSON-LD API with `X-Requested-With: JSONHttpRequest`, 16-hex paste IDs and 13 listed community clients.

### 4.6 Bitwarden Send

**Current status (VERIFIED, HIGH confidence): ACTIVE.** The product page and help centre are live; `/help/send/` redirects to `/help/about-send/`. The 2026 product roundup (2026-11-04) lists four Send enhancements — email verification (March), Send event logs (July), Manage Send policy (August), vault-item sharing via link (October). Release notes 2026.11.0 add "New Send events" for create/edit/delete/access. No deprecation or retirement announcement was found on the blog index, the Send tag page, Bitwarden GitHub issues, or community search. The one "deprecated" hit is PR #12751 (2025-01-14), which removes legacy **upload endpoints**, not the feature. No replacement product was found; "share via link" is built **on** Send.

**Architecture (VERIFIED from official blog + client source).** Link `https://send.bitwarden.com/#<SendID>/<SendKey>`; the fragment is never sent to the server. `sendKeySalt = "bitwarden-send"`, `sendKeyPurpose = "send"`, key derived with `createKeyWithPurpose(128, …)`; the seed lives in the fragment. Source comment: "Despite being called key, the passwordKey is not used for encryption. It is used as a static proof that the client knows the password" — PBKDF2 with `SEND_KDF_ITERATIONS = 100000`. This is the **same access-gate pattern** OneShotLink documents, so it must not be described as two-factor decryption.

**Workflow and limits (VERIFIED).** Send view → New → Text or File → name → content → deletion date (default 7 days; `/help/send-lifespan/` says 30 days in its intro but 31 days later on the same page, and `/help/create-send/` says 30 days — **documented discrepancy**). Who can view: anyone with link / specific emails / password; optional view limit, hidden email, private note. Recipients need no account. Text limit 1,000 encrypted characters; files 500 MB (100 MB mobile) on paid plans; 5 GB total storage for Premium/paid orgs. Official caveat: "These options impact only access to the link itself. The recipient may have saved and still have access to the item's contents even after the link expires."

## 5. Verified vs assumed — explicit separation

**Verified by direct fetch or REA evidence:** all URLs, quotes, prices, limits, release dates, API shapes, file paths, and the REA graph statistics in §1–§4.

**Inferences (not observations), labelled where used:**
- Onetime Secret's five-region architecture implies independent datastores and an outer TLS proxy — inferred from documentation claims, not from infrastructure inspection.
- Yopass's threat-model maturity means "better security process" is **not** a defensible attack line; differentiate on deployment burden and default-included features instead.
- PrivateBin's `#-` confirmation exists to defeat link scanners — directly supported by its encryption-format wiki statement.
- Bitwarden Send and OneShotLink share the "password is an access gate, not a second key" design; neither should be marketed as two-factor decryption.
- The product opportunities in §6 are inferences from the cited observations, not user-validated demand.

**Unknowns that must not be asserted:** Onetime Secret's cipher/KDF/atomic-consume implementation; Yopass's live demo behaviour and browser-extension availability; Privnote's current crypto internals and any formal audit; Password Pusher's details pending §4.4; PrivateBin's modern audit status (privatebin.net's expiration options are now VERIFIED in §4.5, but its file-size cap was not observed); Privnote's 2022 teardown attribution (withdrawn — no source found); Password Pusher's hosted create defaults and API-v2 numeric rate limits; Bitwarden's server-side schema and security whitepaper.

## 6. Product opportunities for OneShotLink

Each item ties an inference to a cited observation.

1. **Reveal ordering is a real, evidence-backed differentiator.** PrivateBin deletes burn pastes at `GET` before decryption (§4.5), and Yopass's GHSA admits a stalled decryption still consumes the link (§4.2). OneShotLink verifies the passphrase and decrypts **before** the atomic consume (`SECURITY.md` invariants 2 and 9). Message: "a failed reveal never burns the secret" — accurate and verifiable locally.
2. **No long-lived browser-held keys.** Yopass admits `localStorage` private keys/management tokens (§4.2); Bitwarden's fragment key is ephemeral by design; Privnote's link-hiding cookies are an exception. OneShotLink's SPA already asserts empty `localStorage`; document it as a property.
3. **Precise, internally consistent security copy.** The original and Privnote both contradict themselves (§4.1, §4.3). OneShotLink's SECURITY_AUDIT explicitly separates observed controls from claims and forbids "zero-knowledge" copy (D-012). This is a trust differentiator that costs no code.
4. **Ship the competitors' documented "not available yet" set selectively.** Onetime Secret lists IP allowlisting, workspace branding, per-domain sign-up validation and custom privacy defaults as missing; audit trail is Beta. Bitwarden's newest features are cloud-first. OneShotLink already has owner receipts, webhooks and a self-host-first story.
5. **Integration surface.** PrivateBin's JSON-LD API and 13 community clients (§4.5) show the value of a published machine-readable contract; OneShotLink has OpenAPI plus dependency-free examples. Full PrivateBin client compatibility is **not** achievable without browser-side encryption — do not claim it.
6. **Do not compete on E2EE.** Yopass and PrivateBin genuinely hold only ciphertext; Bitwarden's fragment key never reaches the server. OneShotLink's server holds the instance key. Per D-012, position on operational safety, honesty and self-host control instead.
7. **Anti-phishing is a category-level pain point.** Krebs 2020/2024 document profitable Privnote lookalikes (§4.3). A self-hostable, bookmarkable instance plus domain-verification guidance is a concrete user-facing answer; a hosted brand would need the same defences.
