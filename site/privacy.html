Privacy

This page describes the software in this repository and the hosted instance we run. If you self-host, the operator of your instance is the data controller; this page is still an accurate description of what the software itself stores.

Last updated: 2026-11-11.

What is stored

Data Where Why, and for how long
The secret itself Redis, as ciphertext only Encrypted with AES-256-GCM under a key derived from the instance secret. Deleted on the first successful reveal, or when the expiry you chose runs out. Plaintext is never written to disk or logged.
A receipt (kind, timestamps, expiry, passphrase flag) Redis, same expiry as the secret So a signed-in sender can see what they created and when. Removed when the secret is revealed or expires.
Account email and password hash Redis, only if you create an account Email for sign-in and receipts; password stored as an Argon2id hash, never in plain text. Kept until the account is deleted.
Session token Redis, keyed by a SHA-256 hash of the token Keeps you signed in; expires on its own, and all other sessions are revoked when you change your password.
Request logs The instance's stdout One line per request: method, path with secret keys redacted, status, duration, request id. No request body, no query string, no cookies, no IP address.

What is not collected

  • No analytics, no tracking pixels, no third-party scripts on this page or in the app.
  • No advertising identifiers, no profiling, no data sold or shared with anyone.
  • No IP addresses or user agents in application logs.
  • No email address unless you sign up for an account or write to us first.

Cookies

One cookie, and only if you sign in: the session. It is HttpOnly, Secure when the instance is served over HTTPS, and SameSite=Lax. There are no marketing or analytics cookies, so there is no consent banner — and no consent to collect, because nothing is tracked.

Your control over it

  • Expiry is yours. The TTL is set when you create a secret and enforced by Redis, not by a cleanup job.
  • Passphrase. An extra access check in front of a secret. It does not make the secret unreadable to the server.
  • Deleting an account. The dashboard has a "Delete account" section: confirm with your password and the account record, its sessions and its receipts are removed immediately. Secrets that have not expired yet stay readable by whoever holds the link until they expire — the handover is theirs to complete, not the account's to cancel.
  • Export. Not implemented. Receipts are metadata about secrets that are designed to disappear; there is little to export.

If we host it for you

The managed instance is not open yet. When it is: the instance runs on a host we control, with TLS, authenticated Redis and daily backups, and the same retention rules above apply. Backups contain ciphertext and account records, are kept for seven days, and are deleted on rotation.

Transport is not end-to-end encrypted. Secrets are encrypted at rest and in transit to the server, and the server can read a revealed secret. If that is not acceptable for a given secret, use an instance you control.

Contact

Privacy questions and account deletion requests: open an issue at the source repository, or use the operator contact published by the instance you are using. This page states what the software does; a lawyer has not reviewed it.
